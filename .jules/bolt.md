## 2024-10-12 - AXIOM Zenith Pillar 1 Zero-Allocation Mode Optimization
**Learning:** `std::map` was used in a hot-path for frequency counting inside `StatisticsEngine::Mode`, resulting in dynamic allocations in violation of AXIOM Zenith Pillar 1 (Zero-Allocation). Furthermore, replacing it with `std::unordered_map` is surprisingly slower on this specific architecture due to constant hash table allocations and re-hashings for each iteration. The fastest and cleanest approach is an allocation-free copy sort using `std::ranges::sort` followed by a single linear pass. This is 3x faster than `std::unordered_map` and completely eliminates heap allocations while maintaining O(1) extra space since it operates on the required local `Vector` copy.
**Action:** Always favor allocation-free in-place algorithms like sorting for frequency analysis instead of standard library associative containers in core modules to comply with Zero-Allocation and maximize speed.
