## YYYY-MM-DD - FastParseDouble zero-allocation optimization
**Learning:** Found unnecessary string allocation when using `std::from_chars` to parse floating-point numbers in C++. The original code created temporary `std::string` copies to pad zeroes for leading/trailing decimals (e.g., `.5` -> `0.5`). C++17's `std::from_chars` naturally handles these edge cases directly. Also learned that older GCC compilers (or Apple clang) without full float support in `from_chars` were falling back to `std::stod`, violating Zenith Pillar 5 (Zero-Exception) and incurring dynamic allocation.
**Action:** Replaced `std::stod` fallback with a zero-allocation `std::strtod` utilizing a stack buffer for typical inputs while retaining dynamic allocation only for very large inputs. Removed the temporary string padding around `std::from_chars`. Next time parsing numbers in C++, avoid unnecessary copies before using modern parsing APIs.
