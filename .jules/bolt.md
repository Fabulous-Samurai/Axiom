## 2024-03-24 - Zero-Allocation from_chars Optimizations
**Learning:** Legacy string parsing fallback in C++ (like `std::stod`) forces heap allocation via `std::string` even when wrapping modern parsing approaches. In core Engine modules (Zenith Pillar 1), this causes latency spikes due to memory fragmentation. However, C++17 `std::from_chars` inherently handles inputs like ".5" or "5." without needing manual padding zeroes. The main missing case is leading '+' signs, which we can parse manually via `std::string_view` iteration.
**Action:** Replace manual `std::string` padding loops and allocations in `FastParseDouble` with direct pointer manipulation on `std::string_view` before passing to `std::from_chars`, satisfying zero-allocation rules without losing edge-case compatibility.
