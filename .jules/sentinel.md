## 2025-02-28 - Unrestricted `eval()` in Subprocess Sandbox
**Vulnerability:** The `scripts/sandbox.py` utility relies on Python's `eval()` within an isolated subprocess but fails to restrict its execution environment (`globals` and `locals`). This allowed arbitrary Python code execution (like file system access via `__import__('os').listdir()`) inside the subprocess, partially defeating the sandbox's purpose if the OS-level subprocess restrictions (like AppContainer or seccomp) fail or are incomplete.
**Learning:** Subprocess isolation is only one layer of defense. Allowing unbounded `eval()` inside that subprocess creates a secondary attack surface that can lead to sandbox escapes or internal process exploitation.
**Prevention:** Always restrict `eval()` execution by passing empty dictionaries (with `__builtins__` explicitly cleared) to enforce a strict math-and-logic-only evaluation environment (e.g., `eval(expr, {'__builtins__': {}}, {})`) in conjunction with OS-level subprocess isolation.
