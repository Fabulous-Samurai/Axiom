## 2025-02-23 - Prevent Command Injection in Python Scripts
**Vulnerability:** Found `subprocess.run` calls passing `shell=True` along with untrusted or partially unsanitized arguments (e.g. `ide_cmd` constructed from external input, or cross-platform paths like `build\run_tests.exe`) in `scripts/sonar_helper.py` and `scripts/zenith_audit_scribe.py`.
**Learning:** Using `shell=True` exposes the system to command injection on posix/windows environments. When migrating to `shell=False`, one must properly split the command into a list and accurately resolve the executable paths manually. For example, replacing `"python"` with `sys.executable` ensures robustness cross-platform, and using `shutil.which` allows resolving script wrappers (like `code` on Windows) which wouldn't execute with `shell=False` without being explicitly targeted.
**Prevention:** Always use lists for `subprocess.run` with `shell=False`. Use `shutil.which` to locate executables, and prefer absolute or dynamic references like `sys.executable` to raw string commands.
