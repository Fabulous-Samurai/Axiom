## 2025-02-23 - Prevented Sandbox Escape and Resource Exhaustion in `scripts/sandbox.py`
**Vulnerability:** `run_isolated_expression` evaluated arbitrary code by passing an expression string wrapped in `eval()` to a python subprocess via `sys.executable -c`. This allowed OS command injection via `__import__('os')` and Denial of Service (DoS) by executing resource-heavy expressions like `[0] * 10**9`.
**Learning:** `eval()` inherently parses and executes everything inside a string. In isolated processes, `eval` executes completely without restriction when `__builtins__` defaults aren't properly overriden, but even with proper overrides, `eval` can be escaped. Passing strings directly to `python -c` further risks unescaped characters mapping to code logic.
**Prevention:** Always use `ast.parse(expr, mode='eval')` with a custom `ast.NodeVisitor` that explicitly checks and validates mathematical `ast.BinOp` limits to prevent Memory exhaustion limits. Only map specific basic operations, dropping attributes and functional calls altogether.
