## 2024-06-05 - SafeMathEvaluator mitigates Python eval Sandbox Escapes
**Vulnerability:** The isolated sandbox expression evaluator was using python's `eval()` on unsanitized user inputs within a subprocess. Though "isolated" via a subprocess and theoretically by AppContainer/seccomp in production, relying solely on Python `eval()` in `scripts/sandbox.py` leaves a critical RCE/Sandbox Escape vector open, allowing execution of code like `__import__('os')`.
**Learning:** `eval()` can never be safely used with untrusted input in Python, regardless of subprocess isolation, because attackers can use built-in functions or import modules to execute arbitrary code or exfiltrate data. The AppContainer/seccomp isolation should act as a secondary defense layer (defense-in-depth), not the primary sanitization logic.
**Prevention:** Always use AST-based restricted execution models (like `ast.parse` combined with an `ast.NodeVisitor` that only whitelists specific operators/nodes, e.g. `ast.BinOp`, `ast.Constant`) to evaluate mathematical expressions securely without executing arbitrary Python code.
