## 2024-05-18 - Restricting Python eval() to safe environments
**Vulnerability:** Unrestricted use of `eval()` in `scripts/sandbox.py`. The `run_isolated_expression` function wraps `eval()` inside a subprocess `sys.executable -c` but leaves it completely unrestricted. This permits arbitrary code execution within the subprocess, such as `__import__('os').listdir('.')` leading to file access, which is a critical sandbox escape vulnerability.
**Learning:** Subprocess isolation (e.g., AppContainer, seccomp) should only act as a secondary defense layer for sandboxes. It is fundamentally unsafe to use Python's `eval()` on untrusted input even within an isolated subprocess, as it bypasses the primary goal of the sandbox (to strictly evaluate AXIOM expressions) and can still leak data or be manipulated if isolation fails.
**Prevention:** To mitigate code injection risks in Python tools without breaking general sandbox functionality, restrict the `eval()` environment (e.g., `eval(expr, {'__builtins__': {}}, {})`). Replace unconstrained eval() with a securely constrained scope containing empty locals and `__builtins__`.
