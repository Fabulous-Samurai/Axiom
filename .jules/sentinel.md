## YYYY-MM-DD - Remote Code Execution (RCE) via `eval()` in Sandbox
**Vulnerability:** The `scripts/sandbox.py` script used `eval()` directly on user-provided input `code = f"import os; print(eval({repr(expression)}))"` without sufficient validation, leading to a sandbox escape.
**Learning:** Python's built-in `eval()` function evaluates arbitrary Python expressions. When used directly on unsanitized user input, it allows full execution of code like `__import__('os').system('...')`.
**Prevention:** Never use `eval()` on unsanitized or untrusted input. Instead, use a safe abstract syntax tree (AST) evaluator (like `ast.literal_eval` or a custom `ast.NodeVisitor`) with a strict whitelist of allowed operators and functions to parse and evaluate mathematical expressions safely.
## YYYY-MM-DD - DoS Vector via Unary Operators and String Multiplication in AST Sandbox
**Vulnerability:** When replacing `eval()` with a custom AST evaluator (`ast.NodeVisitor`), omitting implementations for `ast.UnaryOp` causes the sandbox to crash on basic negative numbers (e.g., `-5`). Furthermore, if `visit_Name` defaults to returning the string representation of an unknown variable, it opens a Denial-of-Service (DoS) vector by allowing large string multiplication (e.g., `"x" * 1000000000`).
**Learning:** A "safe" AST evaluator must implement handlers for all basic mathematical operators (including `ast.UnaryOp`, `ast.Mod`, and `ast.FloorDiv`) to avoid functional regressions. Additionally, operands mapped to operators like `ast.Mult` must be strictly type-checked (e.g., restricted to `int`, `float`, `complex`) to prevent resource exhaustion from sequence repetition.
**Prevention:** Ensure all supported operators are mapped, and validate that operands evaluated in binary and unary operations strictly resolve to safe numerical types rather than defaulting to strings.
