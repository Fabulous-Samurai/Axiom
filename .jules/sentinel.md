## 2024-10-24 - [CRITICAL] Remote Code Execution (RCE) via `eval` in sandbox
**Vulnerability:** The Python expression evaluation in `scripts/sandbox.py` was using the unsafe built-in `eval()` function, which allowed arbitrary code execution, enabling attackers to escape the sandbox via malicious expressions like `__import__('os').listdir('/')` or exhaust memory with `[0] * (10**9)`.
**Learning:** Even when expressions are passed in a "restricted subprocess", using `eval` to evaluate user input provides full Python execution capabilities. This is particularly dangerous when not actually confined by strict OS-level containerization limits (like `AppContainer` or `seccomp`), but it is fundamentally an RCE vulnerability in the application layer regardless.
**Prevention:** Always use safe evaluation mechanisms, such as a custom `ast.NodeVisitor` or `ast.literal_eval`, when parsing or executing arbitrary code from untrusted users. Avoid the `eval()` and `exec()` functions. When implementing custom AST evaluators, strictly type-check nodes and restrict functions to a safe predefined dictionary.
