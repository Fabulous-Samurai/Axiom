## 2024-05-27 - [Command Injection Mitigation in Subprocess Calls]
**Vulnerability:** Found `subprocess.run` calls in `scripts/zenith_audit_scribe.py` and `scripts/sonar_helper.py` that passed `shell=True` along with dynamically constructed command strings, making them susceptible to command injection vulnerabilities.
**Learning:** Using `shell=True` with `subprocess.run` exposes the application to command injection if input parameters are not strictly sanitized. Additionally, when refactoring to `shell=False` on Windows for shell-builtin or system-PATH resolved executables like `code`, `shutil.which` must be explicitly used to resolve the executable path since Python's `subprocess` does not inherently search the environment `PATH` without the shell context. Path concatenations should use `os.path.join`, and interpreter executions should rely on `sys.executable` for safety.
**Prevention:** Always set `shell=False` when calling `subprocess.run` (or avoid explicitly setting it, as it defaults to `False`). Pass commands as a list of arguments rather than a concatenated string. Use tools like `shutil.which` to resolve executable locations safely, and include AST-based unit tests to statically assert that `shell=True` is not introduced in CI or sensitive script components.
