## 2024-05-18 - [Python AST Evaluator Implementation]
**Vulnerability:** Evaluating user-provided mathematical expressions using `eval()` or an AST sandbox lacking strict type and basic operation handling. This exposes the environment to DoS attacks (e.g. `[0] * 10**9`), bypassing restrictions via unhandled edge cases, and unexpected functional regressions on common inputs (like negative numbers).
**Learning:** Python's `ast.literal_eval()` cannot handle mathematical operations. Developing a custom `ast.NodeVisitor` is necessary, but must comprehensively implement methods for `ast.UnaryOp` (for negative numbers), `ast.BinOp` (for arithmetic), and explicit whitelisting in `visit_Name`/`visit_Attribute`. Crucially, operations like `ast.Mult` and `ast.Pow` mapped to `operator.mul` and `operator.pow` must enforce type checks to ensure operands are numeric (`int` or `float`) to prevent sequence multiplication memory exhaustion DoS vectors.
**Prevention:** Avoid `eval()`. Use a custom `ast.NodeVisitor` explicitly mapping and typing required operations. Ensure all standard AST node types (BinOp, UnaryOp, Call, Attribute, Name, Constant) are overridden, returning a SafeEvaluator generic fallback (`ValueError("Unsupported AST node")`) for everything else. Verify path handling using `repr(path)` in f-strings for clean subprocess injection.
