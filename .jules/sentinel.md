## YYYY-MM-DD - Replace Python eval() with Safe AST Evaluator
**Vulnerability:** Python's built-in `eval()` function was being used to evaluate user-supplied math expressions in `scripts/sandbox.py` (via subprocess), exposing the application to arbitrary code execution (RCE).
**Learning:** Even when disabling `__builtins__` (e.g. `eval(expr, {"__builtins__": {}})`), attackers can use Method Resolution Order (MRO) traversal (e.g., `().__class__.__bases__[0].__subclasses__()`) to gain reference to modules like `os` or `sys` and execute system commands. Relying on dictionary whitelists for builtins in `eval()` is fundamentally insufficient for secure sandbox evaluation.
**Prevention:** For mathematical or strictly constrained evaluation, completely replace `eval()` with a custom parser using Python's `ast` module. By implementing an `ast.NodeVisitor`, you can explicitly whitelist safe operations (`ast.Add`, `ast.Sub`), valid function calls (`math.sin`, `math.sqrt`), and completely deny complex node types (e.g., attributes, comprehensions) to enforce a mathematically rigid, secure execution context.
