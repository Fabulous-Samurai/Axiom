## 2024-07-03 - Restricted eval Sandbox Escape Vulnerability
**Vulnerability:** Arbitrary code execution via unrestricted Python `eval()` in `scripts/sandbox.py`. Even though the code is run in a separate subprocess, an attacker could use `__import__` (e.g., `__import__('os').listdir('.')`) to execute arbitrary operating system commands because `eval()` has access to standard builtins by default. Subprocess isolation acts only as a secondary defense layer and does not secure untrusted input execution within the subprocess.
**Learning:** Python's `eval()` is not safe for evaluating untrusted input out of the box. Simply executing it in a subprocess (even with AppContainer or seccomp) does not prevent code execution within that subprocess environment unless the execution scope is strictly limited. Completely replacing `eval()` might break module functionality that relies on general mathematical expression evaluation.
**Prevention:** Always explicitly strip the global execution environment, specifically `__builtins__`, when using `eval()` on untrusted input (e.g., `eval(expr, {'__builtins__': {}}, {})`). When designing tests for restricted AST-evaluated Python sandboxes that block imports and syntax statements (like `while True: pass`), use computationally heavy expressions like `9**9999999` to trigger timeouts reliably. Error outputs in these subprocesses should be routed to `sys.stderr` followed by `sys.exit(1)`.
