## YYYY-MM-DD - [CRITICAL] Arbitrary Code Execution in Sandbox via eval()
**Vulnerability:** The sandbox expression evaluator (`scripts/sandbox.py`) used `eval()` with full environment access, allowing arbitrary code execution, such as reading files via `__import__('os').listdir('.')`.
**Learning:** Using `eval()` even with a `__builtins__` override is insufficient to prevent arbitrary code execution, as attackers can use Method Resolution Order (MRO) traversal or similar techniques, and restricting standard Python features like math module evaluation breaks sandbox utilities. Standard `ast.literal_eval` cannot handle math expressions or method calls.
**Prevention:** Implement a strict AST-based whitelisting approach (e.g., `ast.NodeVisitor`) for evaluating expressions instead of `eval()`. The custom AST evaluator must explicitly allow harmless operations like arithmetic, list/dict construction, and whitelist specific safe function calls (e.g., `math.sin`, `math.sqrt`, `abs`) to prevent sandbox functional regressions while blocking arbitrary system imports or access.
