## 2025-03-05 - Restrict eval in Sandbox Expressions
**Vulnerability:** Arbitrary code execution is possible within `scripts/sandbox.py` because `eval()` is called without restricting its environment. Expressions can access `__builtins__` and subsequently load modules like `os` to execute arbitrary commands or access the file system (e.g., `__import__('os').listdir('.')`). Subprocess isolation alone is insufficient.
**Learning:** `eval()` on user-controlled or untrusted input is dangerous, especially when the globals/locals are unrestricted. The `sandbox.py` mechanism tried to achieve isolation strictly through OS features (seccomp/AppContainer theoretically, threading practically here) but missed language-level restriction. The proper way to sanitize `eval()` without full AST parsing is to explicitly pass `{"__builtins__": {}}` for globals.
**Prevention:** Always restrict the globals (and locals) dictionary passed to `eval()` by explicitly setting `__builtins__` to an empty dictionary, or use `ast.literal_eval` if only simple literals are expected.
